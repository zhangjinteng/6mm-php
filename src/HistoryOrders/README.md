# Historical order CK ownership

`HistoryOrderOwnerQueryService` is used by the total-admin historical order page and the white-label/merchant historical order API. Hosts supply trusted ownership predicates before both COUNT and paginated SELECT; no unfiltered request preloads the users population.

- Total merchant: `home_site_id > 0 AND agent_id > 0`.
- Total white label: `home_site_id > 0 AND agent_id = 0`.
- Total platform: `home_site_id = 0 AND agent_id = 0`.
- Total all: exactly the union above; NULL/negative/invalid owner pairs do not become platform records.
- White-label account: first enabled site by ascending site ID, `agent_id=0`. Child accounts share the tenant owner scope. No site means no rows, never a platform fallback.
- Merchant account: main merchant's home site and main merchant ID; child administrators never use their own site/ID as the owner.

The source-name filter in total admin narrows a white-label tenant to its sites; merchant names select the CK agent ID. Displayed source metadata is resolved from CK site/agent, not from the user's current owner. Owner predicates are generated by host identity/directory code and must never be copied from request SQL.

`hydrateHistoricalRows` only supplements users and external identifiers for the returned page, preserves CK ownership and snapshot user type, and keeps authorized historical rows even when the current user is moved or deleted. Missing public UIDs are shown as missing, not replaced with internal IDs. Keyword/type lookups may still use the business directory; CK ownership remains the result boundary. Page-only condition-order enrichment is retained by each host.

This does not backfill or change the CK tables/ingestion. Reliable filtering requires the recorded owner fields to be correct. Existing keyword, status, sort and host-specific time conversion behavior is retained. Future performance tuning needs separate measurements/index design; the existing sorting key is not site/agent-first.
