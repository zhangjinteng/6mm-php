# Frontend feature-entry configuration

`FeatureConfigStore` defaults to only `trade_ranking` in `control_plane.wl_site_modules` (`module_type=feature`). Opt into `contentFeatures=true` (fifth constructor argument) to also support `news`, `academy`, `help_center`, `feedback`, and `announcement`. Missing records default to disabled and reads never create records. Feature saves leave business module rows and historical data untouched. Changed flags are published to `wl_site_config_snapshots` using the shared site publisher and its entitlement-version rules. The existing table accepts these feature codes; no table/column migration is required.

Platform uses the default policy (first site, ranking-only). Agent passes `enabledSitesOnly=true`, `allowSiteSelection=true`, `schema='control_plane'`, `contentFeatures=true` and a tenant ID derived from its authenticated white-label account. Never accept that tenant ID from an Agent request. The shared service checks tenant/site ownership and status again within the transaction.

Save receives a nonempty subset of allowed feature codes with strict boolean values, plus `expected_updated_at` (nullable). Content-mode detail returns `expected_revision`, a site-scoped fingerprint of all six stored flags; any content-flag save must echo it exactly. It detects concurrent changes even when multiple rows share a timestamp. Legacy ranking-only saves keep their timestamp contract. Writes touch only submitted changed flags, so Platform ranking saves cannot overwrite Agent content switches. The store rejects classification collisions and stale versions, increments timestamps monotonically, skips unchanged writes, and invokes the mandatory host audit callback inside the transaction. The host supplies the authenticated operator ID and namespaced actor for publication. Publication or audit failure rolls back all changes. PostgreSQL uses the existing publisher's lock order and bounded transaction timeouts.

Agent's UI opts in with `content-features`; Platform does not. Content switches remain drafts until save and can be discarded. The separate tenant-wide customer-service switch keeps its immediate-save behavior. Consumer web/APP clients must consume these feature flags to hide entry points; storing flags alone does not change consumer rendering or disable CMS management APIs.

The host retains route/menu permissions and its own actor/audit namespace. Do not cast a white-label account ID into the Platform administrator namespace. This extraction does not publish packages, run migrations or upgrade host dependencies.
